# Example 07 — Multi-Sheet Pipeline with Field Mapping

**Continuation of** examples 01–06. Requires Accounts and Contacts already loaded into Salesforce (examples 01 and 02 must have been executed successfully).

---

## What this example demonstrates

This example is designed to show every major section of the
`web/execconf_generator.html` configuration generator in a single, realistic
pipeline:

| Generator tab | Features exercised |
|---|---|
| **App Configuration** | `processingType: collections`, `stopOnError`, `apiVersion` |
| **Sheets** | 4 sheets — 2 mapped from Excel human-readable headers, 2 built in-memory |
| **Actions** | 9 actions using all four sub-action types (Export, Transform, Copy, Import) |
| **Import / Export** | Load `conf.yaml` into the generator to see the full diagram |

### Feature highlights

- **Sheet field mapping** — the Excel file uses human-readable column headers
  (`Company Name`, `Annual Revenue`, `Contact Email`, …). The `sheets` section
  in the config translates these to Salesforce API names (`Name`,
  `AnnualRevenue`, `WhoId`, …) before any action runs.
- **Multi-sheet Excel input** — `enrichment.xlsx` has two worksheets (`Accounts`
  and `Activities`) that are loaded simultaneously.
- **Dynamic sheet creation via `copySheetAction`** — a condition filter splits
  the `Activities` sheet into two in-memory sheets: all activities and a
  high-priority subset.
- **Cross-sheet ID resolution** — two separate lookup passes resolve email
  addresses to Contact Ids and company names to Account Ids.
- **Idempotent inserts** — an `exportAction` fetches existing Tasks before
  inserting, so the pipeline is safe to re-run.

## Pipeline overview

```
enrichment.xlsx
 ├── [Accounts sheet]──────► Step 1: Get Existing Accounts  (exportAction: merge SF Ids)
 │                                          │
 │                           Step 2: Update Account Enrichment (importAction: update)
 │
 └── [Activities sheet]────► Step 3: Get Contacts            (exportAction → Contacts sheet)
                                          │
                             Step 4: Isolate High-Priority   (copySheetAction: filter Priority=High)
                                      │              └──► High-Priority Activities (in-memory)
                                      │
                             Step 5: Transform Activities     (transformAction: resolve WhoId, WhatId)
                             Step 6: Transform High-Priority  (transformAction: same lookups)
                                      │
                             Step 7: Get Existing Tasks       (exportAction: idempotency check)
                                      │
                             Step 8: Insert Activities        (importAction: insert Task)
                             Step 9: Insert High-Priority     (importAction: insert Task)
```

## Step-by-step

### 1. Generate the Excel input file

```bash
node examples/07-multi-sheet-pipeline/generate-xlsx.js
```

This creates `enrichment.xlsx` in the same folder with two worksheets:

**Accounts** (human-readable headers → API names via `sheets` mapping):

| Company Name | Annual Revenue | Employees | Rating | Description |
|---|---|---|---|---|
| Acme Corporation | 5,000,000 | 250 | Hot | Leading cloud-technology firm… |
| Globex Industries | 12,000,000 | 800 | Warm | Large-scale manufacturing… |
| … | … | … | … | … |

**Activities** (Tasks to create for each contact):

| Contact Email | Company | Task Subject | Due Date | Priority Level | Notes |
|---|---|---|---|---|---|
| john.smith@acme.example.com | Acme Corporation | Q2 Follow-up Call | 2026-06-30 | High | … |
| jane.doe@globex.example.com | Globex Industries | Schedule Product Demo | 2026-06-15 | Normal | … |
| … | … | … | … | … | … |

### 2. Run the pipeline

```bash
node dist/index.js \
  --input  examples/07-multi-sheet-pipeline/enrichment.xlsx \
  --conf   examples/07-multi-sheet-pipeline/conf.yaml
```

Or using the compiled binary:

```bash
./sf-data \
  --input  examples/07-multi-sheet-pipeline/enrichment.xlsx \
  --conf   examples/07-multi-sheet-pipeline/conf.yaml
```

### 3. Expected results

After a successful run:

- **Accounts updated** — `AnnualRevenue`, `NumberOfEmployees`, `Rating`, and
  `Description` are written back to the five Accounts.
- **Tasks inserted** — five new Task records are created in Salesforce (one per
  Contact), linked to the Contact (`WhoId`) and their Account (`WhatId`).
- **High-priority Tasks** — three of the five tasks have `Priority = High`; they
  are also inserted through the dedicated `High-Priority Activities` branch,
  demonstrating that the same records can flow through parallel sheet branches
  (the idempotency check in Step 7 prevents duplicates on re-runs).

## Key concepts illustrated

### Sheet field mapping

```yaml
sheets:
  - name: "Activities"
    fields:
      - name: "Contact Email"   # column name in the Excel file
        apiName: "WhoId"        # Salesforce API field name used in the pipeline
      - name: "Priority Level"
        apiName: "Priority"
```

The mapping happens at read time, so every action sees the API names directly.

### copySheetAction with a condition

```yaml
- name: "Isolate High-Priority Activities"
  inputSheet: "Activities"
  outputSheet: "High-Priority Activities"
  copySheetAction:
    condition: "'${Priority}' === 'High'"   # evaluated per row
    copyFields:
      - name: "WhoId"
        apiName: "WhoId"
      # …
```

`${Priority}` references the `Priority` API-name field of the current row.
Only matching rows are copied; the source sheet is unchanged.

### Cross-sheet ID resolution

```yaml
transformAction:
  fieldsConf:
    - name: "WhoId"
      transformation: "'${Contacts.Email.Id}'"
      # Find row in "Contacts" where Email == current row's WhoId value,
      # then return that row's Id column.
    - name: "WhatId"
      transformation: "'${Accounts.Name.Id}'"
      # Find row in "Accounts" where Name == current row's WhatId value,
      # then return that row's Id column.
```
